# Docker Compose Help Script (`compose-runner.sh`)

Вспомогательный bash-скрипт для массового запуска и остановки docker compose сервисов.
Обходит все подпапки указанного каталога, находит compose-файлы и выполняет в каждой
такой папке выбранное действие (`up -d`, `down`, сборка, параллельный запуск и т.д.).

Идеален для локальных окружений из множества микросервисов: один запуск — и все
проекты в `~/services` подняты, одна команда — и всё остановлено.

## Возможности

- **Автообнаружение сервисов** — ищет `docker-compose.yml`, `docker-compose.yaml`,
  `compose.yml`, `compose.yaml` в подпапках; скрытые папки (`.*`) и `node_modules` пропускает.
- **Последовательный или параллельный режим** — с настраиваемым лимитом задач (`--jobs`).
- **Dry-run** — показывает план действий, ничего не выполняя (работает даже без установленного Docker).
- **Устойчивость к ошибкам** — падение одного сервиса не останавливает остальные;
  в конце печатается сводка, код выхода отражает результат.
- **Поддержка docker compose v2 и docker-compose v1** — определяется автоматически.
- **Прозрачность** — дополнительные флаги можно передать напрямую в compose после `--`.
- Цветной вывод в терминале (отключается через `--no-color` или переменную `NO_COLOR`).

## Требования

- Bash >= 4.3 (Linux / macOS с новым bash / WSL)
- Docker с compose: плагин `docker compose` (v2) или standalone `docker-compose` (v1)

## Установка

```bash
git clone https://github.com/reneget/Docker-compose-help-script || mv compose-runner.sh ../ || rm -rf Docker-compose-help-scriptc
chmod +x compose-runner.sh
```

### по желанию — положить в PATH:
```bash
sudo ln -s "$PWD/compose-runner.sh" /usr/local/bin/compose-runner
```

## Быстрый старт

```bash
# запустить все сервисы во всех подпапках текущего каталога:
./compose-runner.sh

# то же для конкретного каталога:
./compose-runner.sh --dir ~/services
```

Пример вывода:

```
 compose-runner  каталог: /home/user/services
действие: docker compose up -d | режим: последовательно
найдено папок с compose-файлом: 4

==> api
[ OK ]

==> broken
[FAIL] код 1 — вывод выше

==> web
[ OK ]

==> worker
[ OK ]

Итог: успешно 3, ошибок 1, всего 4
```

## Опции

| Опция | Описание |
|---|---|
| `--down` | Остановить сервисы (`docker compose down --remove-orphans`) вместо запуска |
| `--build` | Пересобрать образы (`docker compose up -d --build`) |
| `--pull` | Тянуть свежие образы перед запуском (`up -d --pull always`, только compose v2) |
| `--volumes` | Вместе с `--down`: удалять и тома (`down -v`) |
| `--parallel` | Обрабатывать папки параллельно (по умолчанию — последовательно) |
| `--jobs N` | Лимит параллельных задач (по умолчанию `4`; работает с `--parallel`) |
| `--depth N` | Глубина вложенности подпапок (по умолчанию `1` — только прямые подпапки) |
| `--dir PATH` | Базовый каталог (по умолчанию — текущий) |
| `--dry-run` | Только показать, что будет выполнено, ничего не запуская |
| `--verbose` | Подробный вывод (в параллельном режиме — логи и успешных папок) |
| `--no-color` | Отключить цветной вывод |
| `-- ФЛАГИ` | Всё после `--` передаётся напрямую в `docker compose` |
| `-h`, `--help` | Справка |

## Примеры

```bash
# обычный запуск всех сервисов
./compose-runner.sh

# запуск с пересборкой образов
./compose-runner.sh --build

# параллельный запуск, до 8 задач одновременно
./compose-runner.sh --parallel --jobs 8

# остановить всё
./compose-runner.sh --down

# остановить всё вместе с томами
./compose-runner.sh --down --volumes

# посмотреть, что будет сделано, без выполнения
./compose-runner.sh --dry-run --down

# поиск сервисов на два уровня вложенности + сборка
./compose-runner.sh --dir /opt/services --depth 2 --build

# передать дополнительные флаги в docker compose
./compose-runner.sh -- --force-recreate
```

## Как это работает

1. Скрипт сканирует базовый каталог (`--dir`, по умолчанию текущий) на глубину
   `--depth` (по умолчанию 1 — прямые подпапки).
2. Папка считается сервисом, если в ней лежит один из compose-файлов:
   `docker-compose.yml`, `docker-compose.yaml`, `compose.yml`, `compose.yaml`.
3. В каждой найденной папке выполняется выбранное действие — `docker compose up -d`
   (с `--build` / `--pull` при необходимости) или `docker compose down --remove-orphans`.
4. Ошибка в одной папке не прерывает обработку остальных; в конце печатается сводка
   «успешно / ошибок / всего».

В параллельном режиме вывод каждого задания собирается в отдельный лог и печатается
по мере завершения заданий — вывод не перемешивается. `--verbose` дополнительно
показывает логи и успешных папок. Ctrl+C в параллельном режиме корректно
останавливает все фоновые задачи.

`--dry-run` работает даже без установленного Docker — удобно проверить, какие папки
будут обработаны.

## Коды выхода

| Код | Значение |
|---|---|
| `0` | Все команды выполнены успешно (или нечего делать) |
| `1` | Хотя бы в одной папке команда завершилась с ошибкой |
| `2` | Неверные аргументы, каталог не найден, docker compose не установлен |
